# Chat providers and agentic document search

After updating, run `python src/manage.py migrate` with the project's Python environment. Restart the backend and rebuild the frontend. The active localhost deployment uses PostgreSQL and has been migrated successfully. The separate legacy `data/db.sqlite3` was left untouched; it requires the historical application upgrade path before use with this version.

In **Application Configuration → AI Settings**, enable AI and configure embeddings as before. The new OpenAI (ChatGPT), Anthropic (Claude), and Mistral sections each accept a server-side API key and a comma-separated list of model IDs available to that API account. Select chat models that support function/tool calling. Save the configuration, then refresh the model list in the chat toolbar. Multiple providers can be enabled together. Removing a key or its model list removes that provider from the picker. Existing Ollama/OpenAI-compatible configuration remains available as “Configured backend”. Chat selection does not change classification or embedding settings.

Keys are masked on settings reads and retained when an unchanged masked value is saved. Clearing the key disables the provider. Keys use the same database storage and administrative permissions as the existing LLM key; protect database backups accordingly. Ordinary document viewers receive only model IDs and provider labels. The chat endpoint rejects models outside the administrator's configured list. Availability here means configured, not a successful live credential or account-access check.

The dashboard agent combines semantic retrieval with lexical matches, can read bounded portions of discovered documents, and searches again when needed. Search/read budgets and repeated-query caching limit work. All retrieval and reading use the user's permitted document set. Answers provide source links and the chat displays search/read activity. Missing indexes still trigger indexing and explain that the index is not ready. For large archives, lexical ranking currently scans the already-loaded permitted document text; an indexed lexical backend is a useful future scaling improvement.

The shared chat panel offers model selection, stop, retry, history per document, and scrolling that does not pull readers away from earlier messages. Switching documents cancels an active response.

## Provider transport references

The implementation reuses the installed LlamaIndex OpenAI-compatible client and fixed provider endpoints. OpenAI supports chat completions and function tools ([API reference](https://developers.openai.com/api/reference/cli/resources/chat)); Mistral documents the compatible request structure and endpoint ([migration guide](https://docs.mistral.ai/resources/migration-guides)). Claude uses Anthropic's official OpenAI SDK compatibility endpoint ([compatibility documentation](https://platform.claude.com/docs/en/cli-sdks-libraries/libraries/openai-sdk)). Anthropic describes that layer as primarily for evaluation; native Claude API support is a follow-up for production-specific features such as prompt caching and strict schema guarantees. Provider calls were tested with mocks, not paid live requests.
